# ForgeTube / Video Studio

**ForgeTube** is a reliable, local-first, CLI-only documentary video production system. It turns historically researched documentary topics into structured, frame-accurate, image-based documentary projects rendered through Remotion with FFmpeg media processing support.

The first reference project is a 10–15 minute documentary covering the complete history of Rome, but the tool is fully reusable for arbitrary historical subjects and long-form topics.

---

## Architectural Principles & Constraints

1. **CLI-First & Fully Local**: No web application, no REST/GraphQL API, no Electron shell, no background service, and no cloud database. Every operation is executed directly as local processes reading and writing the project directory.
2. **Research Before Writing**: Scripts are strictly grounded in verifiable, scholarly sources and structured historical claims.
3. **Structured Decoupling**: AI agents and generative processes output validated JSON schemas. Video rendering code remains decoupled and reusable across all projects.
4. **Manual Google Flow Checkpoint**: Image prompts are exported into formatted prompt manifests (`storyboard/prompts/batch_NN.md`). The system halts at the `WAITING_FOR_MANUAL_IMAGES` checkpoint until real images generated by the user in Google Flow are imported.
5. **Frame-Accurate Timeline**: Editorial durations (seconds) are deterministically compiled into integer frame timings with collision avoidance and smooth transition overlaps.
6. **Calibration Math & Human Control**: Normalized bounding boxes `[0..1]` permit fine-grained framing and Ken Burns camera movements without destructive overwrites to original generated images.
7. **Resumable by Default**: Every stage can run on its own, unchanged work is reused, and interrupted renders pick up from finished chunks.

## Prerequisites

- **Bun** 1.3+ for the CLI, scripts and tests
- **Node.js** 20+ for the render worker only
- **FFmpeg** 7+ and ffprobe on PATH
- **Chrome or Edge** for rendering, or set `BROWSER_EXECUTABLE`
- **Python with `edge_tts`** for narration (online; the text is sent to Microsoft)
- **earshot** for sound effects and music ranking (optional)

Tool paths go in `forgetube.config.json` (git-ignored):

```json
{ "python": "<python with edge_tts>", "earshot": "<earshot launcher>" }
```

## Workflow

Claude Code writes the words and the CLI does the rest. In Claude Code, run `/doc-film`, or use the commands below. `vs` stands for `bun run bin/video-studio.js`.

1. **Create:** `vs project create --name "Rome" --topic "The history of Rome" --target-minutes 12`
2. **Research:** `research brief`, `research import`, `research approve`
3. **Script:** `script brief`, `script import`, `script approve`. Fix one segment with `script set-segment`.
4. **Storyboard:** `storyboard brief`, `storyboard import`, `storyboard approve`, `prompts export`
5. **Images:** generate them in Google Flow from `storyboard/prompts/batch_NN.md`, then run `assets import --input <dir> --order`.
6. **Crop:** `calibration apply-preset --preset gemini-watermark`, `calibration contact-sheet`, `calibration set` for single scenes, `calibration approve`
7. **Voice:** `audio voice`, `timeline compile`, and `storyboard rebalance` if a shot is too long
8. **Sound:** `audio sfx render`, `audio music scan`, `audio music plan`, `audio mix`
9. **Render:** `render --mode draft`, `audio approve`, `render --mode final`

Check progress at any time:

```bash
bun run bin/video-studio.js pipeline status -p <id>
```

## How rendering resumes

Video is rendered silent, in chunks stored by content under `render/chunks/`. An interrupted render reuses finished chunks. A change to one chapter re-renders only that chapter, and an audio-only change only re-muxes.
